# Customer-Journey-Map

**Задание:**

Опишите формализованные требования к приложению (Погода):

не менее 8 требований, среди них:

– минимум 4 функциональных (по крайней мере 2 — пользовательские, 2 — системные);

– минимум 2 нефункциональных;

присвойте каждому требованию уникальный идентификатор;

убедитесь, что требования обладают признаками качественных требований: полнота, ясность, непротиворечивость, осуществимость, верифицируемость.

Составьте карту пользовательского пути (Customer Journey Map):

Опишите не менее 7 этапов использования вашего приложения. 

Для каждого этапа отразите:

Задачи пользователя

Его действия

Чувства и мысли

Возможные барьеры

Решения или способы преодоления барьеров

**ДЗ_2**

**Задание:**
В задании «Методы формализации требований» вы уже описывали требования к ПО. 
Теперь их необходимо представить в ТЗ или SRS. Для реализации можно выбрать любой стандарт.

Разработать документ. Состав документа зависит от выбранного стандарта и ПО, которое разрабатывается. Необходимо описать документ с учетом всех разделов стандарта.
Разделы необходимо использовать все (См. состав ТЗ в презентации занятия).
Подразделы только значимые с точки зрения функционала.
Варианты использования достаточно указывать верхнеуровневые.
Требования должны быть корректными по отношению к выбранному продукту.
Результат: согласно заданию, созданное ТЗ или SRS к заданному программному продукту.
